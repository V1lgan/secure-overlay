# Архитектура проекта

## 1. Проектное решение
* **Язык:** Python 3.11+
* **Конкурентность:** asyncio
* **Транспорт:** TCP
* **Сериализация кадра:** бинарный `struct` (big-endian)
* **Сериализация payload:** JSON
* **Конфигурация:** YAML (`configs/*.yaml`)

## 2. Целевые параметры
* `MAX_FRAME_PAYLOAD` = 65536 байт
* `PROTOCOL_VERSION` = 1

## 3. Границы этапа 1 (Транспорт)
В рамках первого этапа реализован транспортный уровень:
* Кадрирование (24-байтовый заголовок).
* Потоковый декодер `FrameBuffer`, обрабатывающий частичные чтения из TCP.
* RPC-корреляция по `request_id` с обработкой тайм-аутов.
* Базовый TCP-сервер и клиент.

## 4. Инженерное сравнение форматов (E1-8)
Для сериализации payload были рассмотрены форматы JSON и MessagePack. 
Был проведен замер на тестовом наборе данных (10000 итераций):

| Формат | Размер (байт) | Скорость (оп/сек) |
|---|---|---|
| JSON | 299 | 168,170 |
| MessagePack | 196 | 424,594 |

**Вывод:** MessagePack обеспечивает выигрыш по размеру на 34.4% и более высокую скорость обработки. Для дальнейших этапов в качестве формата payload выбран JSON как более простой и читаемый для отладки, но при необходимости (например, для бинарных данных или туннелей) MessagePack является запасным вариантом.
